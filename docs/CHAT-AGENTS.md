# Chat 检索 Agent 架构（第一阶段）

普通 Chat 使用“授权能力目录 → 路由 → 空间 Agent → 证据汇总 → 引用校验”。
Chat+ 的 Skill、附件和文件生成流程保持独立。

## 行为

- 自动模式仅向路由模型提供可访问空间的名称、描述及最近对话，不预先搜索全部空间的文档。
- 每轮最多选择 3 个 Agent。无法匹配时提示指定空间或补充信息，不回退到所有空间。
- 指定空间时直接使用对应 Agent。只有一个候选能力时也直接使用它。
- 自动模式的“检索能力”可限制参与路由的空间；未授权的能力 ID 会被服务端拒绝。
- 新建自动会话不绑定任意一个 workspace；每条回答记录实际运行的 Agent 和来源。
- 原有自动会话的 workspace_id 不批量迁移，仍可继续使用。

Workspace Agent 先在自己的空间内按全文相关度、上传时间排序，最多向模型提供 200 篇文档的摘要目录，
再选最多 5 篇读取正文。每篇选择一个最多 6,000 字符的相关窗口，不再固定截取开头。
候选截断会记录并展示，但仍可能漏掉不匹配关键词且较旧的文档；尚未实现向量检索或完整章节索引。
建议为空间填写明确的产品、主题、版本和典型问题描述，以改善路由。

Agent 目前串行执行，各自最多 90 秒，路由最多 45 秒。使用同一数据库会话，不并发共享 AsyncSession。
单个模型/格式/超时失败不丢弃其他 Agent 的成功结果。

## 证据与来源

`Evidence` 统一描述文档和未来外部来源：稳定 ID、片段、标题、所属 Agent、workspace、URL、定位信息、
内容类型、产品版本与时间字段。连接器提供真实 ID 和 URL，模型只引用本轮分配的 `[S1]` 等编号。

- 最终来源列表仅包含正文实际引用的证据，检索候选不会自动成为来源。
- 引用校验忽略代码示例，拒绝未知编号；缺少引用或编号无效时最多修复一次，仍失败则显示错误。
- 校验确保引用存在，不代表已实现逐句语义蕴含验证。模型仍需遵守依据证据回答的约束。
- `processed_text` 指归类流程提取/翻译的正文；`summary` 指摘要，不能称为逐字原文。
- 回顾历史但没有新证据时可引用 `conversation`，明确标为未经独立核验的会话历史。
- 前端可点击引用查看片段、空间及内容类型。内部文档下载仍按 doc_id 走鉴权端点；不持久保存临时签名 URL。
- Markdown、Word、PDF 导出保留引用编号、来源归属、文档 ID 或外部 URL。

## 接口与存储

- `GET /chat/agents`：当前用户可用的能力描述。
- `POST /chat`、`POST /chat/stream`：新增可选 `agent_ids`。省略/null 表示所有授权能力可参与路由；
  `[]` 表示不启用任何检索能力。显式 workspace 不得与能力过滤冲突。
- 最终响应增加 `agent_runs`；原有 `answer`、`sources`、`conversation_id` 保留。
- SSE 仍使用 `stage`、`thinking`、`token`、`done`，新增路由和按 Agent 检索阶段。
  最新阶段可在重连时恢复。`done` 中的答案与来源是最终校验结果。
- `messages.sources` 保持 JSONB，兼容旧记录；新 `messages.retrieval` 保存错误与运行状态。
- 升级前运行常规迁移流程，新增 `044_message_retrieval.sql`。本次开发未对业务数据库执行迁移。
- 任务仍保存在单进程内存中，服务重启不恢复在途任务。

## 添加外部能力

当前没有启用 Palo Alto 外部连接器，不会向这些站点发送请求。
下一阶段可分别实现 Community、官方 KB 和官方 Docs：

1. 实现 `RetrievalAgent`，提供 `AgentDescriptor` 与 `retrieve()`；访问接口由连接器负责。
2. 返回统一 `RetrievalResult/Evidence`，保留原始链接、文章编号、产品版本及发布/检索时间。
3. 在能力目录、权限解析和 `build_registry()` 中注册配置完成且用户获授权的连接器。
   扩展请求的候选范围传递，使外部能力不依赖 workspace_id；不得仅凭客户端 ID 启用能力。
4. 复用 `AgentRegistry` 路由、证据汇总、引用校验和来源 UI；无需增加站点专用答案格式。
5. 外发搜索词只含必要的产品/版本/报错，内部正文和整段历史不直接发送给站点。

新增连接器需要另行确认站点接口、认证、限流和版本匹配方式。当前接口是第一阶段扩展基础，
尚不是自动加载任意插件的运行时。

通过标准测试脚本使用隔离测试库，禁止对业务数据库运行 pytest。
前端 `e2e/chat-agents.spec.ts` 使用模拟接口验证能力过滤、引用片段、代码示例不误转引用及刷新恢复；
