# Chat 全局索引检索

普通 Chat 使用“授权空间 → 并行读取完整索引 → 全局选择文档 → 并行获取证据 → 综合回答”。
Chat+ 的 Skill、附件和文件生成流程保持独立。

## 检索范围与调用次数

- 自动模式覆盖当前用户全部有权限的空间；手动指定空间仍限制到该空间。
  不根据空间名称、描述、产品目录或模型置信度预先排除空间。
- Workspace Agent 保留独立空间边界。索引与正文 SQL 均限制 workspace、ready 状态和未删除状态。
  `RetrievalAgent` Protocol 和外部来源的 `Evidence` 契约继续保留。
- 并行读取各空间的完整标题、分类、标签、摘要、上传时间与真实文档 ID，没有 200 篇上限。
  每个并发数据库任务使用独立 AsyncSession，模型调用期间不占用这些子会话。
- 索引在预算内时，所有空间合并为一次模型选择，随后一次模型综合回答。
  不再每 40 篇调用一次模型，也不再每个空间单独选择。
- 普通主题问题按全局相关性选择 top-K（默认 10）；产品/文档概览不套用固定 top-K。
  模型返回 `doc_ids`，兼容旧提示词的 `fetch_numbers` / `doc_numbers`。
  只接受给定索引中的真实 ID，未知 ID 无法创建来源或越权读取文档。
- 索引超预算时按实际输入大小分批初选，随后把各批候选合并复选；每个原始文档都参与初选。
  这是上下文不足时的近似检索，不保证与无限上下文的全局排序完全等价。
- `index` 模式返回索引证据，`fetch` 模式只读取选中文档正文。
  `select_excerpt()` 保留最多 6,000 字符的相关窗口，并记录对应位置；尚未实现完整章节检索。
- 综合回答的证据仍超预算时，分批生成带原始引用编号的摘要，再综合回答。
  中间摘要只能引用自身批次中的真实证据；不会把生成的摘要伪装成新的原始文档。
  单篇索引/证据过大或无法继续缩减时明确返回输入预算错误，不静默漏掉后续文档。
- LLM 调用使用引擎原有的闲置超时，去掉普通 Chat 检索和引用修复的 90 秒总时限。
  取消请求会取消并等待并发子任务清理；单个空间读取失败仍允许其他空间继续回答。

## 上传记录查询

`temporal_query_service.py` 仅识别明确的文档上传/新增清单问题，不使用宽泛关键词命中。
“最近上传了什么”“本周有哪些新文档”走 SQL；“最新 PAN-OS 配置”“新版文档有哪些配置变化”仍走内容检索。
无法确定范围、包含产品限定或要求内容比较的问题不会被强行当成上传清单。

- 所有范围仍来自经过授权校验的 registry。查询不读取正文，也不调用检索或回答模型。
- 日期按 Asia/Shanghai 计算，支持今天、昨天、本周、上周、本月、上月及数字天数/周数。
  未指定的“最近”默认过去 7 天；回答明确显示起止时间。
- 使用 `documents.created_at`，兼容迁移库的 timestamptz 与旧 ORM 的 UTC 无时区列。
  这是上传入库时间，不代表文件实际修改时间、产品版本发布时间或内容变化。
- 默认按时间倒序显示最新 20 篇，同时显示完整匹配数量；明确要求“所有/all”时输出完整清单。
  空结果会给出清晰说明。每一条真实文档都有来源引用。

## 证据、引用与降级

- 检索成功但没有匹配文档（包括空空间、没有授权空间）时，改用模型已有通用知识和当前对话历史回答。
  返回 `sources=[]`、`warning="knowledge_fallback"`，明确标注“未引用知识库文档”，
  不要求模型生成或修复引用。该标注保留在流式结果、历史恢复和导出中。
  不会把通用知识伪装成知识库实际存有的文档，也不声称查过最新官方资料。
  实际检索失败仍报告错误；上传记录为空仍如实展示数据库结果，不编造记录。
- `Evidence` 包含真实文档 ID、片段、Agent、workspace、URL、定位和时间字段。
  正常回答只展示实际引用的来源，支持 `[S1]` 等编号点击查看和鉴权下载。
- 验证会忽略代码示例；正文里的引用链接不能使用模型自行生成的目标 URL。
- 缺少引用或出现未知引用时尝试修复一次。仍无效或修复调用失败时，保留初稿，移除正文引用，
  返回 `sources=[]` 与 `warning="citation_degraded"`，界面明确标注“来源未验证”。
  此时答案不具备经过引用校验的来源保证，不能把检索候选直接补成引用。
- 警告随 API/SSE、会话历史、刷新恢复和 Markdown/Word/PDF 导出保留。
  当前默认采用上述 best-effort 行为，未新增管理员 strict/best_effort 设置界面。
- 引用存在性校验不等于逐句事实核验。概览与压缩摘要仍受模型提取质量影响。
- 历史来源兼容 `document_catalog`、`document_count` 和 `conversation`；会话回顾标注为未经独立核验。

## 配置与接口

`.env` 可配置（修改后需重建/重启服务）：

| 变量 | 默认值 | 含义 |
|---|---:|---|
| `CHAT_RETRIEVAL_CONCURRENCY` | 4 | 并行任务组上限 |
| `CHAT_RETRIEVAL_TOP_K` | 10 | 普通主题检索的全局文档数 |
| `CHAT_PROMPT_BUDGET_BYTES` | 180000 | 每次提示词的 UTF-8 字节预算 |

字节预算不是精确 token 数，需要根据实际模型调整并预留输出空间。
1000 篇 × 250 tokens = 250,000 tokens，超过 200K 上下文，不能直接假设一次调用可容纳。

- `/chat` 和 `/chat/stream` 共享检索流程；旧 `agent_ids` 仅做兼容授权校验，不再限制范围。
- 普通 Chat 不恢复能力勾选或 category 过滤。`GET /chat/agents` 保留为描述接口。
- `agent_runs` 保留实际空间、状态、证据数；内容检索记录 `indexed_count`，上传记录记录 `document_count`。
- `messages.sources`、`messages.retrieval` 仍用 JSONB，无新增数据库迁移。
- 在途生成仍保存在单进程内存中，服务重启不能恢复进行中的任务。
- Community、官方 KB、官方 Docs 连接器尚未启用。

## 验证

`test_chat_full_index.py` 覆盖跨空间一次选择、完整索引、权限、时间戳和流式回答。
`test_chat_optimizations.py` 覆盖 1000 篇候选的预算分批/复选、并发独立会话、取消清理、摘要来源和降级保存。
`test_chat_temporal_query.py` 覆盖意图误判、日期边界、权限、数量限制和上传记录不调用检索模型。
`test_chat_agents.py` 保留引用、导出和部分失败兼容验证。
仅对隔离测试库运行 pytest；前端 `e2e/chat-agents.spec.ts` 使用模拟接口验证引用、警告和刷新恢复。
