# Chat 完整空间索引检索

普通 Chat 使用“授权空间 → 完整索引检索 → 取回相关证据 → 综合回答 → 引用校验”。
Chat+ 的 Skill、附件和文件生成流程保持独立。

## 当前行为

- 自动模式遍历当前用户所有有权限的空间，不根据空间名称、描述、产品或分类预先筛选空间。
- 手动指定空间时读取该空间的完整索引。每个 Workspace Agent 的 SQL 仍严格限定所属空间。
- 已移除模型空间路由、产品目录专用分支、最近更新专用分支及前端“检索能力”勾选过滤。
  产品概览、最近更新和具体配置问题均使用同一个索引检索及综合回答流程。
- 每个空间按上传时间和文档 ID 分页扫描所有已归类且未删除的文档，每页最多 40 篇。
  这是每批输入大小，不是总数上限；不再限制 200 篇候选、3 个空间或最多 5 篇返回文档。
- 索引包含完整标题、分类、标签、摘要和上传时间，不先读取所有正文。
  模型逐页判断相关文档：`index` 模式返回索引证据；`fetch` 模式再读取所选文档的正文。
  本页无匹配也会继续扫描后续页，编号只能指向本页真实文档。
- 正文仍选择最多 6,000 字符的相关窗口，来源同时保留相应索引信息及定位说明。
  若问题需要窗口外的完整章节，当前仍可能需要更具体的追问；尚未实现完整章节索引。
- 每个索引页的模型调用最多 90 秒。空间串行执行，共用同一 AsyncSession。
  大空间允许继续处理后续页，不再被整个空间 90 秒的期限提前截断。
- 每条回答保存实际运行空间、`indexed_count`、证据数量和失败状态。
  前端“本轮检索范围”显示已扫描索引数量；单个空间失败时保留其他空间的结果并提示未完成。
- 新建自动会话不绑定任意 workspace；历史会话及已有引用保持可用。

当前没有原文件修改时间。索引中的 `uploaded_at` 表示上传入库时间，不能当作文件的实际修改日期。
全索引扫描会增加模型调用量与等待时间；候选来自整个索引，最终相关性选择仍由模型判断。

## 证据与来源

`Evidence` 统一描述文档和未来外部来源：稳定 ID、片段、标题、所属 Agent、workspace、URL、定位信息、
内容类型、产品版本与时间字段。模型只能引用本轮分配的 `[S1]` 等编号。

- 最终来源仅包含回答实际引用的证据，候选文档不会自动成为引用。
- 引用校验忽略代码示例，拒绝未知编号；缺少引用或编号无效时最多修复一次。
- 校验保证引用存在，不代表逐句语义蕴含验证。事实性回答仍必须依据检索证据。
- `document_metadata` 是文档索引信息；`processed_text` 是处理后的正文片段；`summary` 是摘要。
  含正文的来源片段将索引信息与正文片段分开标记，定位字段说明所选正文范围。
- 旧的 `document_catalog` 来源和 `document_count` 保留兼容展示，新流程不再生成产品目录统计。
- 回顾历史但没有新证据时可引用 `conversation`，明确标为未经独立核验的会话历史。
- 可点击引用查看片段、空间及内容类型。下载原文仍按 doc_id 走鉴权端点。
- Markdown、Word、PDF 导出保留引用编号、来源归属、文档 ID 或外部 URL。

## 接口与存储

- `POST /chat`、`POST /chat/stream`：省略 workspace_id 表示所有授权空间；指定 ID 表示对应空间。
- 旧的 `agent_ids` 参数保留兼容校验，但不再限制索引范围；前端不再发送此参数。
  `category_id` 同样不再预先过滤普通 Chat 的完整空间索引。文档管理的分类和检索功能不受影响。
- `GET /chat/agents` 保留为兼容的授权能力描述接口，不再用于 Chat 前端过滤。
- SSE 继续使用 `stage`、`thinking`、`token`、`done`，没有模型路由阶段。
  `done` 中的答案与来源为最终引用校验结果，重连仍可恢复最新检索阶段。
- `messages.sources` 和 `messages.retrieval` 继续使用 JSONB，本次无需新增数据库迁移。
- 在途生成仍保存在单进程内存中，服务重启不能恢复进行中的任务。

## 后续外部能力

Community、官方 KB、官方 Docs 尚未启用。以后可通过 `RetrievalAgent` 和 `Evidence` 接入，
但本次不恢复按空间名称或产品目录过滤的模型路由。
连接器必须保留真实 URL、文章编号、产品版本和时间，且仅为已配置且用户获授权的来源注册。

## 验证

后端 `tests/test_chat_full_index.py` 验证超过 200 篇文档、多个授权空间、时区、历史来源和流式综合回答。
`tests/test_chat_agents.py` 验证授权范围、证据引用、失败处理及导出兼容。
仅使用隔离测试库，禁止对业务数据库运行 pytest。
前端 `e2e/chat-agents.spec.ts` 使用模拟接口验证勾选过滤已移除、索引证据、引用点击及刷新恢复。
